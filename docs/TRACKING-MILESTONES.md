# CASPIAN LOGISTICS — архитектура за Milestone Tracking v0.3

**Състояние:** работещ локален API прототип + публикуван браузърен демо модул. **НЯМА реално свързани пристанища, железници, фериботи или доставчици на GPS.**

## Демонстрация

- На GitHub Pages: отвори \`tracking.html\`; въведи **DEMO-0001** или **DEMO-0002**. Добави тестови събития с формуляра, виж историята, нулирай и експортирай JSON. Тези записи са само в браузъра.
- В локалния API: \`node tracking-api/server.mjs\` (Node 24+). Слуша по подразбиране **127.0.0.1:8787**, със SQLite база в игнорираната папка \`tracking-api/data/\`. Отвори \`http://127.0.0.1:8787/tracking.html\`; локалният браузърен изглед може да чете събития от API вместо вградените демо данни.
- За писане през API е нужен дълъг таен токен в **TRACKING_API_TOKEN** (никога не се добавя към клиентски код или GitHub). Режимът на данните остава **demo/verified=false**, докато няма сертифицирани интеграции.

## Модел на събитие

Приемаме нормализирани събития с полета:
\`reference\`, \`event_id\` (уникален за пратката), \`type\`, \`location\`, \`mode\`, \`observed_at\` (ISO-8601), \`recorded_at\`, \`source\`, \`verified\`, \`demo\`, \`note\`.

В сървъра **event_id** дава идемпотентност: повторно изпращане не добавя втори запис. Събитията се пазят, сортират по време и могат да се доставят през Server-Sent Events до разрешен клиент. Отбелязваме кога е наблюдавано събитието и кога е записано, защото разликата е важна при забавен обмен между системите.

Поддържани видове: регистриране, приемане, вход/изход от терминал, натоварване на влак/ферибот, отплаване, пристигане, митническо освобождаване, доставка, съобщено забавяне.

## HTTP API (локален прототип)

| Метод | Път | Цел |
|---|---|---|
| GET | /api/health | Диагностика |
| GET | /api/shipments/:reference | Пратка + хронология |
| GET | /api/shipments/:reference/stream | SSE за нови събития |
| POST | /api/shipments | Въвеждане на тестова пратка, Bearer token |
| POST | /api/events | Въвеждане на нормализирано събитие, Bearer token |

\`POST /api/events\` пример:

\`\`\`json
{
  "reference":"DEMO-0001",
  "event_id":"terminal-msg-00001",
  "type":"terminal_in",
  "location":"Алат, Азербайджан",
  "mode":"terminal",
  "observed_at":"2026-11-24T08:00:00Z",
  "note":"Тестово събитие"
}
\`\`\`

Сървърът задава източник „Тестово API събитие“ и **не позволява** потребителското тяло да маркира запис като потвърден.

## Предстоящи интеграции

1. **Global DTC** — да се поиска достъп до API документацията, sandbox, условия и право за споделяне на статуси с трети страни. https://globaldtc.com/
2. **ASCO Tracking** — публично проследяване, но публичен API не е потвърден. https://tracking.asco.az/
3. **Баку / Актау Port-to-Port** — обмен чрез терминални системи; не е равнозначно на свободен външен API. https://www.digitalizetrade.org/projects/port-port-exchange-project-caspian-corridor
4. **ЖП оператори и TOS** — отделни технически/договорни проверки и права за обработка на данни.
5. Конекторите трябва да извършват **mapping** от конкретен операторски код към нормализиран тип, проверка на подпис/идентичност, дедупликация, ретраи и журнал на грешките.

## Преди публично включване

Текущият API е **локален прототип**, не публично готова услуга. Нужни са: HTTPS, автентикация и права за четене на пратки (за да не може всеки да проверява чужди товари); управление на организациите; секрети във vault; rate limits; журнал за всички промени; CORS allowlist; защита срещу replay/фалшификация; retention, GDPR/DPA; мониторинг; устойчивост при прекъсване и реална проверка на доставчици. Не отваряй \`TRACKING_HOST=0.0.0.0\` за интернет преди тези мерки.

Предиктивни закъснения и актуални ETA **не са реализирани**; съществува само ясно обозначен демонстрационен сигнал за забавяне.

## Тестове

\`npm test\` — проверка на API здраве, демо маркировки, липсващи номера, авторизация, идемпотентност, невалидни събития и сервиране на фронтенда. Не са необходими външни услуги.
